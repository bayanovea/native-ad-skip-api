- **Importer** imports a sheet (`--batch` = the sheet name, default the md file name) as batches of at most `--max-items N` (default 30): a larger sheet becomes `<sheet>-p1`, `-p2`, … of near-equal size in `position` order (`splitSheet()`: 104 → 26 × 4, not 30/30/30/14; the sheet is shuffled, so there are no video boundaries to keep), a sheet within the limit keeps its name. A re-import finds the sheet's items by `(sheet, item_code)` in whichever part they live; new items go to a new part (`-p<next>`, never into a part someone holds), which takes the first part's `reviews_needed` / `excluded` unless given; a new part name that already holds another sheet's items fails the import. It registers each batch in `prv_review_batches` with `--reviews N` (how many reviewers must finish it, default 1), `--exclude CODE[,CODE]` (registered codes that may never take it, e.g. the first reviewer of a subset sheet) and `--priority urgent|important|optional` (where it sorts on the page, default `important`; `optional` = a pass for when there is time, `urgent` is what the judge sends from prod); for an existing batch a value other than the stored one fails the import (never silently re-routes a batch), an option left out is not checked. `--assignee` is gone (fails with a hint: batches are first come). It names the md verdicts' reviewer with `--reviewer CODE` (default `bayanovea`); per batch, when the newly imported verdicts leave it unfinished for that reviewer it is locked on them (only if they may take it), when they finish it their lock is released; a re-run that imports nothing touches no lock. md verdicts of a `--reviewer` in the batch's `excluded` list, or into a batch locked by another reviewer (read `FOR UPDATE` in the import transaction, so a concurrent take waits), fail the import (exit 1, nothing written; an md whose verdicts are all skipped passes): one holder per batch. It reads `<sheet>.md` + `<sheet>.key.tsv` (written by `adskip sheet` in `native-ad-skip-eval`; blind `C<n>` sheets only, `K<n>` conflict sheets are rejected). Every item needs `Proposed as:`, an http(s) `Link:` and a `Verdict:` line. The verdict is the text on the `Verdict:` line; when that line is empty (as `adskip sheet` writes it), the first non-empty line after it must be the verdict (`Verdict: ` / `not an ad` / reason, the style of the 2026-10-12 sheets) and any other text there fails the import. The remaining lines are the comment, up to a markdown heading (`#`…`######` + space) or a `---` rule line, which ends the item. It first copies the md to `<sheet>.md.bak-YYYYMMDDHHMMSS` (suffix `-1`, `-2` instead of overwriting) and never writes the md. One transaction: items `ON CONFLICT ((COALESCE(sheet, batch)), item_code) DO NOTHING`, and an item already in the sheet must be the same stretch (`native_id`, `start`, `end`, `proposed`) or the import fails, so a regenerated sheet or a wrong `--batch` never attaches verdicts to the wrong item; md verdicts (`source='import'`) go through `recordVerdict` and only for items with no verdict yet from anyone, so re-running after more md marks adds only the new ones. An unknown verdict text fails the whole import (nothing written).
- **Split** (`split-review-batch.js <batch> [--max-items N]`, for batches imported before the limit) cuts a batch the importer's way in one transaction: the parts get its `reviews_needed` / `excluded` / `priority`, its items move with their `sheet` set (verdicts stay on them, so re-import and export by sheet name still work), its row is deleted. Refuses a locked batch (release it on the page first), one within the limit, one whose part names exist and one already split (names its parts). A reviewer with verdicts in the old batch comes back to each part under the come-back rule.
- **Export** (`export-review-verdicts.sh <sheet|batch> [reviewer]`: a sheet name exports all its parts, a part name only that part) writes the latest verdict per decided item (with a reviewer: their latest per item they decided, into `<name>.<reviewer>.verdicts.tsv`; an unregistered code exits 1) as `provider native_id category start end verdict item note` for `adskip review -file`: `sponsor`/`self_promotion` → `gold_missing` (category = the verdict), `not_ad` → `model_wrong`, `unclear` → `definition_unclear` (category = first proposed). Times with one decimal; a `gold_missing` row carries the item's effective bounds (those of the latest verdict with bounds, of the given reviewer when one is given, else the item's: an assessor's correction becomes the gold interval), the other rows the item's own (they judge the stretch the model proposed; an ai item's own are its entry's whole seconds, rounded inward from the cues, so an adopted sheet exports narrower than before: its old bounds stay in `flagged_by`, export it before adopting). Note = comment with tabs/newlines collapsed. Exits 1 (nothing written) on an unknown sheet or batch; creates `review/` if missing and writes through `<file>.tmp` + `mv`, so a failed query never leaves a truncated TSV.
- **Bounds import** (`import-verdict-bounds.js <tsv> [--dry-run]`, once for the times assessors typed into comments before the bounds fields existed; the owner-checked table is `~/Web/data/review/bounds-2026-10.tsv`, private): rows `sheet item_code reviewer start end` (`sheet` = a sheet or part name, `reviewer` `-` = the author of the item's latest verdict, times as the page reads them, `#` comments). Per row it appends a verdict copying the reviewer's latest verdict and comment plus the bounds (`source = 'import'`, `bounds_source = 'import'`; an ai item's entry moves as on the page), in one transaction with every touched batch row locked. Skips with the reason: no verdict by the reviewer, a later verdict by someone else, latest not a keep, invalid bounds (short ones are valid, as on the page), already these bounds. A malformed line, an unknown item or reviewer → exit 1, nothing written.
- **Below-threshold import** (`import-below-threshold.js [--sheet NAME] [--priority P] [--max-items N] [--min-seconds S] [--empty-only] [--dry-run]`, the DB env of the other scripts; inside the app container or with prod's `AI_MIN_SEGMENT_SECONDS` in the env, which sets the default `--min-seconds`): the AI rows' `hidden` entries with reason `confidence` (sponsor below `medium`, self_promotion below `high`; with `--min-seconds` below `AI_MIN_SEGMENT_SECONDS` also those hidden as `short`; never `review` or `unconfirmed`, the latter has its `D` item) of rows with a run, withdrawn ones included, become **ai** items on their row (`kind = 'ai'`, `video_id`), so a verdict acts as on any ai item: a keep serves the entry (unless short), `not_ad` / `unclear` hide it on review; codes `B<n>`, bounds = the entry's, `proposed` = its category, `cues` = the run's transcript cues overlapping the bounds, `link` at start − 2 s, `flagged_by` = `detect run <id>: <category> <confidence>, <len> s, hidden: <reason>`, cut into parts the importer's way (`reviews_needed` 1, default priority `optional`). Entries shorter than `--min-seconds` (default `AI_MIN_SEGMENT_SECONDS`, `lib/ai-rules.js`) are left out: a short mention is not served at any confidence while the threshold stands, and the 2026-10-24 dry run had 82 of 161 under 5 s, mostly 1–5 s sponsor mentions from four streams; `--min-seconds 0` keeps them. A segment already in `prv_review_items` (same `native_id`, bounds ± 0.05 s, category, any sheet, or a sheet item holding it as adopt matches it; `reviewRepository.hasItemAt`) is skipped, so a later run imports only new detections; default sheet `ai-below-threshold-<YYYY-MM-DD>`, a sheet that already has items is refused (exit 1). `--empty-only` = only AI rows with empty `data`, not withdrawn (funnel stage 9). Their verdicts export like any item. `--served N [--seed S]` (no `--empty-only` / `--min-seconds`) instead sends a blind sample of what viewers get: shuffles the AI rows not withdrawn with non-empty `data` (seeded, `rng` / `shuffle` of `lib/review-sheet.js`, shared with `subset-review-sheet.js`, default seed 1), takes one random served entry per native_id until N, leaving out entries already in review and those whose bounds a verdict set (`source: review`); codes `S<n>`, `flagged_by` = `detect run <id>: <category> <confidence>, <len> s, served`, default sheet `ai-served-<YYYY-MM-DD>`, default priority `urgent`. A verdict acts as on any ai item (`not_ad` hides the entry, a keep with bounds corrects its timing).
- **Adopt** (`adopt-review-items.js <sheet> [--dry-run]`, once for `ai-below-threshold-2026-10-24`, whose `B<n>` were imported as `kind = 'sheet'` before the rows kept `hidden`; after `ai regate --backfill` and after exporting the sheet; inside the app container, `applyVerdict` reads `AI_MIN_SEGMENT_SECONDS`): a sheet item whose category matches one entry of its native_id's AI rows (`data` or `hidden`) sitting inside the item's bounds by < 1 s at each end (`entryInsideSheetItem`, `lib/review-sheet.js`: the old importer kept cue times to 0.1 s, entries are rounded inward) becomes an ai item at the entry's bounds (`reviewRepository.adoptItem`: `kind`, `video_id`, `start` / `end`, so later verdicts and the judge find the entry; the old bounds go to a `flagged_by` line `adopted: item bounds a-b`; only items of the old importer, `flagged_by` … `below the publish threshold`: a md sheet's items would fail its re-import), then its latest verdict goes through `applyVerdict` (`from` = the entry, `to` = the item's effective bounds; a `not_ad` / `unclear` after a keep with bounds hides the entry at those bounds, where a later page verdict looks); undecided items are converted only. One transaction per item under its batch row lock (`withBatchLock`, then the AI rows); no match or more than one (e.g. the entry in two AI rows of the native_id) leaves it a sheet item. Prints a line per item (`<code> <native_id> <old bounds> -> video <id> <entry> (<reason>|served) <verdict> applied|unchanged`) and `N items: M matched, A applied, U unmatched, K already ai items, O not below-threshold items, F failed` (exit 1 when any failed, e.g. bounds overlapping a served entry: that item rolls back); a re-run skips ai items.
- **Video flags export** (`export-video-flags.sh`) writes the latest value per `(native_id, flag)` of `prv_review_video_flags` as `provider native_id flag value reviewer set_at` to `review/video-flags.tsv`. Today one flag: `track_mismatch` (subtitle track ≠ player), the input for the eval repo's timing-clean slice and the drift audit.
- **Detector sync** (`scripts/sync-detector.sh <eval checkout>`): the detector lives in the eval repo (`~/Web/native-ad-skip-eval`, under `internal/`, so not importable; CI builds from this repo alone), so the product keeps a copy: the script copies `detector`, `transcript`, `vtt`, `provider`, `ytdlp` into `ai/` with the import path rewritten to `odedohbest/video-calculate/ai/…` (`provider` takes platforms as config: `provider.Def` = name + URL templates, `platform.go` renders them; the product registers its one Def from env in `ai/platform`, see Key Directories), drops `claudecli.go` (eval-only transport) and the eval's key-file lookup (`apiKeyPath`: the key comes from `ANTHROPIC_API_KEY` only; `openai.go` reads `OPENAI_API_KEY` only and is copied as is), keeps the product-owned `detector/fixture.go`, `fixture_test.go`, `apikey_test.go`, copies `prompts/<PROMPT>.md` to `ai/prompts/`, writes the eval commit to `ai/SOURCE`, warns when the eval's `anthropic-sdk-go` or `openai-go/v3` version differs from `go.mod` (then `go get` + `go mod tidy` + `go mod vendor`) and ends with `go build ./ai/...`. **Eval first, then sync**: never edit the copied packages or the detector prompt here; change and score them in the eval repo (its `TestProductPackagesImportOnlyEachOther` keeps the five packages free of `store` / `netguard`), commit there, then sync. A new prompt file also needs `AI_PROMPT` (default `/app/ai/prompts/v2.2.md`, not wired in compose) or a new default in `ai/pipeline/detect.go`; the prompt sha in every `prv_ai_runs` row tells which videos ran under which. `ai/prompts/judge-v1.md` is product-owned (no eval copy yet).
- **`--recompute-ratings`** (`calculator.RecomputeRatings`, `calculator/recompute.go`): for every video with a `{prefix}video_calculateds` row, in its own transaction: locks that row (`FOR UPDATE`, as the vote handler and a recalculation do), computes the ratings with the calculator's rule (see Calculation Algorithm), updates only the segment rows whose rating differs and rewrites the JSON entries' `rating` (sparse; entry order and other fields kept) only when one changed. Never touches boundaries, markups or `is_new`. 10 videos in parallel; a failing video is logged (`Recompute ratings failed: <video_id>: <err>`) and the binary exits 1 at the end. For prv it then does the same for every `prv_ai_video_calculateds` row in any state (its `data` JSON only, `hidden` has no ratings; under that row's `FOR UPDATE`; `Recompute ratings failed: AI row <video_id>: <err>`). Last line: `Recompute ratings finish: N videos processed, M segments changed, K video_calculateds rewritten` (prv: `, A prv_ai_video_calculateds rewritten`).
- **`ai regate [--backfill]`** (`ai/pipeline/regate.go`, by hand after a rule change; no heartbeat): for every `prv_ai_video_calculateds` row in any state (withdrawn too: restore serves their `data`), in its own transaction under the `video_calculateds` lock then the AI row's `FOR UPDATE` (the vote handlers' order), puts each entry of `data` ∪ `hidden` where the current rules say: a `reason: review` entry never moves, nor does an `unconfirmed` one (the second model's veto) unless its latest ai-item verdict is a keep; an entry whose latest ai-item verdict is a keep (at its effective bounds, whenever decided: `judge.EntryKeepsAll`, the judge's `entryKeeps` query without the `judged_at` bound) skips the confidence rule; the length rule (`AI_MIN_SEGMENT_SECONDS`) applies to all, confidence before short. Entries entering `data` get the votes' rating (`calculator.WithVoteRatings`), entries leaving it drop theirs; both arrays sorted by `start`; a row is written only when something moved; never withdraws (a row left with empty `data` serves nothing); served entries never overlap, so a hidden entry overlapping a served one (a keep moved an entry over it) stays hidden. `--backfill` first rebuilds an empty `hidden` from the row's run (object `raw_output` + transcript, the way `finish()` does): the segments that fail the current rules and overlap nothing in `data` (the detector's segments never overlap, so one that does is that entry, moved or re-categorised by a verdict; one a `not_ad` verdict removed passed the rules at the threshold it was published with, so none comes back: backfill before raising `AI_MIN_SEGMENT_SECONDS`); a run that no longer parses or validates is logged (`ai regate: run <id> not backfilled: …`) and skipped; a filled `hidden` is never rebuilt, so a second run adds nothing. Log per changed row `ai regate: video <video_id>: N served, M hidden (+in -out), K backfilled`, last line `ai regate: R rows, C changed, F failed (min S s)`; a failed row is logged (`ai regate: video <video_id> failed: …`) and the binary exits 1 at the end.
- **Audit** (`ai audit`, `ai/audit/`, cron hourly at minute 45, `flock -n /tmp/ai-audit.lock`; with `AI_AUDIT_ENABLED` off a tick only deletes its heartbeat row): replaces the owner's "check these batches". A batch is due when it has as many finishers as `reviews_needed` (`finishedSQL` = `finishedOf` of `prv/repository/review.js`), no holder, a finisher other than the owner (`OwnerReviewer` = `bayanovea`), its newest verdict between 30 min (`settle`, time for a finisher to fix a verdict) and 7 days old (`window`, so switching on never audits the whole history) and its newest verdict id above the latest audit's `watermark`. Per batch: one `REPEATABLE READ READ ONLY` transaction reads items, every verdict, the latest `track_mismatch` per native_id, no row lock (the audit writes nothing but its row and the message). **Rule findings** (`rules.go`, fixed severity, numbers in `evidence`): `eval_ready` (owner: a sheet item, action `eval_import`), `judge_false_alarm` (backlog: every item of a video from a judge `review` / `withdraw` kept, with the judge's decision, author and reason from `flagged_by`), `rubber_stamp` (owner: a non-owner finisher with ≥ 10 verdicts, median gap < 20 s, no `not_ad` / `unclear`, bounds or comment; action `blind_subset`, sample ≤ 12), `precision` (owner when an `ai-served` item is `not_ad` / `unclear`, else info; keep share and Wilson 95 % lower bound per proposed category), `agreement` (two or more finishers disagree: owner below 80 %, else info), `category_flip`, `bounds`, `track_mismatch` (info). Item source = the first `flagged_by` line (`itemSource`). **Model findings**: one Messages call (`AI_AUDIT_MODEL`, prompt `ai/prompts/audit-v1.md`, `AI_CLIENT` as the judge's, `fixture` = `<batch>.audit.json`) with the metrics, rule findings and items (cues cut to 600 chars, every finisher's latest verdict, comment and bounds); it adds only `comment` / `other` findings and a summary, a finding naming no code of the batch is dropped (`metrics.model_findings_dropped`), text cut to 400. A transport error writes nothing (failed batch, retried next tick); an answer that fails the schema writes the row with the rule findings and `llm_error`. Each finding is `{kind, severity: owner|backlog|info, items, text, evidence, action: {type, params, note}, new}`; `new` = the batch's previous row has no finding of the same kind on the same items, so a re-audit after later verdicts (a new row, the old one stays) repeats nothing. `action` is a suggestion nothing acts on yet. **Reaching the owner**: the latest audit of each batch with a new `owner` / `backlog` finding and not hidden shows on `/admin/review` for `bayanovea` only (see Routes → `admin-review.js`; not access control, only keeps it off the assessors' page); with `AI_AUDIT_TELEGRAM=on` (default off: Telegram is unreachable from the prod host, `docs/backlog/telegram-blocked-from-prod-host.md`), after the insert the tick sends one plain-text message (no `parse_mode`, no host, no token, ≤ 4000 chars) with those findings to `TELEGRAM_CHAT_ID` (the alerting chat) via `TELEGRAM_API_URL`, then sets `notified_at`; each tick first resends unnotified rows of the last 7 days with such findings, so a failed send goes out once later and switching the ping on does not send the page-only history. Heartbeat `ai_audit`: `failed_videos` = failed batches and sends. Switch on: deploy with it off, run the manual line above on one recent finished batch, check the block and the message, then set the repository variable `AI_AUDIT_ENABLED=on` and redeploy with the running sha. `ai audit <batch>` ignores the switch, the owner-only rule, the settle, the window and the watermark, refuses a batch that is not finished (exit 1, nothing written), records and pings like a tick and writes no heartbeat; a run that audits needs `ANTHROPIC_API_KEY` (not for `fixture`) and, with `AI_AUDIT_TELEGRAM=on`, `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` (startup error naming the missing one).
