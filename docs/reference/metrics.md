# Prometheus Metrics, Grafana, Alerting

Moved out of CLAUDE.md on 2026-11-04 (instruction-size limit); CLAUDE.md keeps a summary with the
invariants. A "see X" names a section of CLAUDE.md or of another file in `docs/reference/`.

Two custom counters, the heartbeat and AI gauges and one HTTP histogram are exposed on `GET /metrics` (served by `server.js`, not by `express-prom-bundle`'s autoregister — `/metrics` is in `excludeRoutes` so it doesn't record itself).

**`video_calculated_lookup_total{outcome, provider, source}`** — outcomes of `GET /video-calculated`. `provider` is `prv` / `rt` / `yt`. `source` is the table served: `ai` (prv `match` / `backfilled` served from `prv_ai_video_calculateds`) or `human` (everything else, `not_found` / `not_calculated` and rt / yt included). `outcome` is one of:

| Outcome | Definition |
|---|---|
| `match` | Request supplied `duration`; row found by `(native_id, duration ± 2)`; `VideoCalculated` row exists. |
| `backfilled` | Request supplied `duration`; no `± 2` match; a row with `duration = NULL` existed and was just updated to the request's duration; `VideoCalculated` row exists. |
| `mismatch` | Request supplied `duration`; no `± 2` match; no `NULL` row to backfill; helper fell through to `findOne({ native_id })` and returned a row whose stored duration differs by > 2 s; `VideoCalculated` row exists. |
| `no_duration` | Request had no `duration` query param (legacy client); helper fell through directly to `findOne({ native_id })`; `VideoCalculated` row exists. |
| `not_calculated` | Helper returned a `Video` (any of the four above) but no `VideoCalculated` row was found; caller overrides the helper's outcome to `not_calculated`. |
| `not_found` | Helper returned `null` (no `Video` row matched at all). |

The first five outcomes are emitted by `lib/find-video-for-read.js`; `not_calculated` is derived in the route handler when `VideoCalculated.findOne` returns null. prv's legacy `!req.query.v` branch in `prv/routes/videos.js` (`legacyUnversioned`, prv only) does **not** emit a lookup outcome — it only increments `request_without_version_total`; on rt/yt a request without `v` is counted there too and then takes the normal path with its outcome.

**`request_without_version_total{method, provider}`** — count of client requests that omit the `v` query/body param, on every provider (prv: its old clients; rt/yt clients always send `v`). `method` is the route key (`GET /video-calculated`, `POST /markup`).

**`calculator_last_run_timestamp_seconds{provider}`**, **`calculator_last_success_timestamp_seconds{provider}`**, **`calculator_failed_videos{provider}`** — unix time of the Go calculator's last run / last run with no failed video, and the number of videos that failed in the last run (0 included), from `calculator_heartbeats` (one row per provider, see Calculation Algorithm step 4), read on every scrape by one shared `collect()` callback that `registerCalculatorHeartbeat(sequelize)` in `prometheus-wrapper.js` installs (called from `server.js` after `bootstrap()`, so the module stays DB-free for `test/prometheus-wrapper.test.js`). A provider without a row (or, for the success gauge, with `last_success_at` NULL) has no series; a failing query is logged once and leaves all three gauges empty for that scrape, the rest of `/metrics` is unaffected. The `CalculatorStale` alert watches the success gauge and `CalculatorFailedVideos` the failed-videos one (see Grafana → Alerting). The `ai` command's rows show up as `provider="ai_detect"` / `"ai_judge"` / `"ai_audit"`.

**`ai_videos{status}`**, **`ai_cost_usd{kind}`** (`detect` = SUM of `prv_ai_runs.cost_usd`, `judge` = of `prv_ai_judgements.cost_usd`, `confirm` = of `prv_ai_confirmations.cost_usd`, `audit` = of `prv_review_audits.cost_usd`), **`ai_cost_usd_24h{kind}`** (the same over rows with `created_at` in the last 24 h; the cost alert and panel read it, not `increase()` of a gauge), **`ai_judgements{decision, by}`**, **`ai_review_open`** (ai review items without a verdict, below-threshold ones included) — AI-first state from four plain queries per scrape (one refresh shared by the gauges) (`registerAiMetrics(sequelize)`, registered next to the heartbeat in `server.js`). A failing query is logged once and leaves them empty (`ai_review_open`, label-less, reads 0). **`ai_first_enabled`** (label-less, set once at registration from `AI_FIRST` as `lib/find-ai-calculated.js` read it at boot: 1 = the AI rows are served) tells the dashboard whether the "ready to serve" rows reach clients. Grafana: all of them on `ai-pipeline.json` (see AI-first segments → Dashboard); `infrastructure.json` keeps only the heartbeat stat.

**`http_request_duration_seconds_{bucket|count|sum}{method, path, status_code}`** — `express-prom-bundle` histogram with buckets `[0.05, 0.1, 0.25, 0.5, 1, 2.5]`. `path` is normalized via `normalizePath` rules in `server.js` so dynamic segments collapse (`/admin/video/12345` → `/admin/video/#video_id`, `/markups/42` → `/markups/#id`, `/admin/review/<batch>` → `/admin/review/#batch` except `/admin/review/decide` and `/admin/review/reviewers`, `…/<batch>/take|release` → `/admin/review/#batch/take|release`, `/admin/video/<id>/ai/withdraw|review` → `/admin/video/#video_id/ai/withdraw|review`, `/admin/review/audits/<id>/hide` → `/admin/review/audits/#id/hide`, etc.). The default `url-value-parser` catches any unmapped numeric/UUID IDs as defense-in-depth.

**Storage / scrape:** Prometheus (`config/prometheus.yml`; `prometheus.dev.yml` is the dev stack's) scrapes every 30 s: `app:3022/metrics` (job `native-ad-skip-api`), `node-exporter:9100` (job `node`: host disk and memory; `pid: host`, the host's `/` read-only at `/host`) and, through `blackbox-exporter:9115` (job `blackbox`, module `http_2xx` of `config/blackbox.yml`: IPv4, 2xx, HTTPS required, 10 s timeout), `https://${API_HOST}/` and `https://${LANDING_HOST}/`, i.e. through public DNS, nginx and TLS (from the prod host itself, a hairpin to its own IP; a check from outside is still open: `docs/backlog/alerting-host-and-external-checks.md`). Neither exporter publishes a port. Prometheus stores data on the `prometheus_data` named Docker volume (mounted at `/prometheus` in the container; project name `COMPOSE_PROJECT` → stable volume `<project>_prometheus_data`, see Deployment). Retention is bounded by **both** `--storage.tsdb.retention.time=30d` and `--storage.tsdb.retention.size=2GB`; whichever hits first wins, so the volume can never exceed ~2 GB. The size cap exists because the `path` label on `http_request_duration_seconds` is effectively unbounded (unmatched/404 URLs each create their own series), which previously grew the volume to 35 GB. Prometheus does not downsample — reclaiming space means dropping whole 2 h blocks, which it does on startup and every compaction cycle.

**Grafana:** the `grafana` service in `docker-compose.yml` (the old `../native-ad-skip-grafana` repo is superseded). All services attach to the external `main-network` (precondition on the host: `docker network create main-network`). Datasources are provisioned from `grafana/provisioning/datasources/datasources.yml`: Prometheus at `http://prometheus:9090`, Postgres at `${DB_HOST}:5432` (= `host.docker.internal`). Dashboards are provisioned from `grafana/dashboards`; ad-hoc UI edits live only on the `<project>_grafana_data` volume. Data links that call the API's GET admin endpoints (vote/markup delete, update-rating) in `tables.json` and `assessors.json` take the token from a `verifyBearerToken` textbox variable that starts empty: type `AUTH_TOKEN` into it, or open the dashboard with `?var-verifyBearerToken=…`. Never commit a token value into a dashboard. Grafana listens on plain HTTP `:3024` (`http://${HOST_IP}:3024/`, which `GF_SERVER_ROOT_URL` gets from the compose env for the links in alerts; `.claude/skills/ai-dashboard-check` reads the base URL from `GRAFANA_URL`), open to the internet by a Timeweb cloud firewall rule and protected only by its login (anonymous access and sign-up disabled). Plain HTTP means the password crosses the network unencrypted, and its Postgres datasource uses the app's read-write `DB_USER`. Docker-published ports bypass host `ufw`; the **Timeweb cloud firewall** is the only filter, so to close Grafana remove the 3024 rule there (or bind it to `127.0.0.1` and use `ssh -L 3024:localhost:3024`).

**Alerting:** provisioned from the repo, folder "native-ad-skip-api", evaluation group `api` every minute, on the Prometheus datasource (`StaleMarkups` on the Postgres one). `grafana/provisioning/alerting/rules.yml` has eleven rules; `noDataState: OK` unless said otherwise (a rule removed from the file stays in Grafana and keeps firing until its uid is listed under `deleteRules` there, as `lookup-not-found-share` is since 2026-10-19):
- `CalculatorStale` — age of the last success over the provider's limit, `> 1` for 5 min: `(time() - max by (provider) (calculator_last_success_timestamp_seconds{…}))` divided by 600 for prv/rt/yt, 900 for `ai_detect`, 7200 for `ai_judge` and `ai_audit` (four selectors joined by `or`); no data at all = the calculator never ran, so `noDataState: Alerting`. A switched-off `ai` command deletes its heartbeat row, so it has no series rather than an aging one.
- `Http5xx` — `sum(increase(http_request_duration_seconds_count{status_code=~"5.."}[5m])) > 5` for 5 min.
- `ApiDown` — `up{job="native-ad-skip-api"}` below 1 for 2 min (queried unfiltered: `up == 0` is empty while healthy); no `up` series = Prometheus is not scraping the app, so `noDataState: Alerting`.
- `HttpLatencyP95` — `histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m]))) > 1` for 5 min (the top bucket is 2.5 s, the quantile saturates there).
- `CalculatorFailedVideos` — `max by (provider) (calculator_failed_videos) > 0` for 3 min (three cron runs); the summary says to look for `Calculate video failed: <video_id>` in `docker logs` (for the `ai` providers: `ai detect:` / `ai judge:` / `ai audit:` lines). For the `ai` providers a failed video is an infrastructure failure (a video's own outcome is not counted; a detect tick whose every fetch failed counts: prv refusing the host, the summary says to set `AI_DETECT_ENABLED=off`), and one failed tick holds the gauge until the next one (5 min / 1 h): `docs/backlog/ai-detect-failed-videos-alert-window.md`.
- `AiCostDaily` — `sum(ai_cost_usd_24h) > 30` for 5 min: above a full budget day (prod `AI_DAILY_BUDGET_VIDEOS` 2000 at `AI_BATCH_MAX` 10 since 2026-11-07 × terra batch alone, `AI_SECOND_ENABLED` off, ~$0.013 a video measured on prod ≈ $26; back to 20 with the budget after 2026-11-09); the audit's cents per finished batch (`prv_review_audits`, kind `audit`) count too; Grafana cannot read the env, so change the threshold with the budget or the second model. `AI_DETECT_ENABLED=off` stops the spend.
- `HostDiskLow` — `min by (mountpoint) (node_filesystem_avail_bytes / node_filesystem_size_bytes)` over `ext4|xfs|btrfs` below 0.15 for 10 min (Postgres, `docker logs` and images are not capped); no series = node-exporter not scraped, so `noDataState: Alerting`.
- `HostMemoryLow` — `node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes` below 0.10 for 10 min.
- `ProbeFailed` — `min by (instance) (probe_success{job="blackbox"})` below 1 for 5 min (unfiltered, as `ApiDown`): nginx down, an expired or invalid certificate, DNS, or the app behind nginx; `ApiDown` scrapes `app:3022` directly and sees none of the first three. No series = blackbox-exporter not scraped, so `noDataState: Alerting`.
- `TlsCertExpiry` — `min by (instance) (probe_ssl_earliest_cert_expiry{job="blackbox"}) - time()` below 14 days for 1 h: certbot renews at 30 days left, so it fires only after two weeks of failed renewals (missing data is `ProbeFailed`'s).
- `StaleMarkups` — Postgres: `COUNT(*)` of `markups` with `is_new = true`, `deleted_at IS NULL` and `"updatedAt"` older than 10 min, `> 0` for 5 min (every `is_new = true` writer is a Sequelize update, which bumps `updatedAt`; prv only, rt/yt have no data).

`policies.yml` routes everything to the one contact point `telegram` (group by alertname, `group_wait 30s`, `group_interval 5m`, `repeat_interval 4h`). The contact point is **not** a file in that directory: Compose renders it from the `configs:` block of `docker-compose.yml` into `/etc/grafana/provisioning/alerting/contact-points.yml` (needs Compose 2.23.1+, prod has 2.40.3), with `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` from the deploy environment — GitHub Actions secrets, never in the repo. Grafana's own `$VAR` expansion cannot be used for the chat id: Grafana 12.3.1 turns an env var that parses as a number into a YAML number and the Telegram integration requires `chatid` to be a string, so provisioning fails and Grafana refuses to start. **Missing secrets:** with both variables empty Grafana exits 1 at start (`Failed to provision alerting … could not find Bot Token in settings`) and crash-loops under `restart: unless-stopped`; `docker compose up -d` still returns 0, so the deploy job passes and `app` / `prometheus` are unaffected, but Grafana is down until the two secrets exist. Verified locally with Compose 2.40.3 and `grafana/grafana:12.3.1` on 2026-10-18.
