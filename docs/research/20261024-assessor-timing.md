# Асессоры правят границы AI-сегмента: стоит ли

Дата: 2026-10-24. Вопрос владельца: сделать так, чтобы асессор на `/admin/review`, кроме
вердикта, указывал правильный тайминг сегмента. Ожидаемые минусы: скорость разметки упадёт
примерно вдвое, система усложнится. Эта заметка собирает факты, чтобы решать осознанно.

Источники: eval-репозиторий (`~/Web/native-ad-skip-eval`, store `~/Web/data/adskip.db`,
held-out прогон `2026-10-23-…-v2.2-batch-nt`, 217 видео), экспорты вердиктов с прода
(`~/Web/data/review/*.verdicts.tsv`, 387 пунктов), локальный дамп прода от 2026-10-21, код этого
репозитория. Цифры по границам посчитаны одноразовым скриптом по правилам продукта (sponsor ≥
medium, self_promotion = high, ≥ 5 с); его SCORE / s/h совпадают с зафиксированными (0.40 / 2.08).

## Выводы

1. **Ошибка границ есть, большая и односторонняя: детектор режет *внутрь* рекламы.** На 159
   совпавших с «сырым» человеческим gold сегментах медиана ошибки старта +3.6 с (поздно), конца
   −5.3 с (рано); p75 15–18 с, p90 24–48 с. 85 % сегментов лежат внутри рекламы, только 8 % режут
   > 2 с контента на каком-то краю, ~2 % режут > 5 с. У 52 % сегментов на краю остаётся > 10 с
   рекламы. Из всего пропущенного рекламного времени (49 %) треть, ≈ 16 % всей рекламы, это края
   уже найденных сегментов.
2. **Значит, правка границ почти целиком про полноту (recall), а не про безопасность.** Правило
   владельца «только то, в чём уверены, даже ценой пропусков» сегодня выполняется: контент
   режется в основном ложными сегментами целиком, не краями. После ревью метрика 2.1 с/ч делится
   примерно пополам между 9 ложными сегментами и ~100 краевыми перебегами по ~1.6 с, что внутри
   шума самого gold (± 2 с).
3. **Человеческая точность границ сама ~± 2 с в лучшем случае и часто расходится крупно.** Пары
   пользовательских разметок одной рекламы: |Δstart| p50 1 с, но p75 9 с, p90 35 с; оба края в
   пределах 2 с лишь у 41 % пар. В дампе прода из 252 групп с ≥ 2 разметками в одном бакете конец
   сходится в пределах 2 с у 57 % (p90 100 с). Расхождение не про глазомер, а про определение:
   где начинается реклама, на подводке («а теперь о спонсоре») или на самом питче; где кончается,
   на последнем слове о продукте или после возврата к теме. Без письменного правила границ любая
   правка асессора унаследует этот разброс.
4. **Инструмент для правки отсутствует, и это главный источник замедления.** Плеер prv открыт в
   другой вкладке, обратно позицию он не отдаёт (нет iframe / API), на странице нет ни парсера
   `m:ss`, ни контекста транскрипта за границами сегмента (`cues` = только реплики внутри
   границ). Сегодня асессор при желании вручную печатает время в комментарий: так сделано в 14 из
   459 вердиктов с комментарием, все 14 про «реклама продолжается дальше / началась раньше», ни
   одного про отрезанный контент. Если править по плееру, нужно отсматривать до p90 ≈ 48 с с
   каждого края, замедление ≥ 2× реально. Если править по тексту (выбор первой/последней реплики
   рекламы в показанном транскрипте ± 60 с), замедление заметно меньше, точность = длина реплики
   (p50 2.0 с, p90 3.7 с), тот же потолок, что у детектора.
5. **Охват ограничен тем, сколько видео вообще проходит через асессоров.** Пункты `kind = 'ai'`
   создаёт только судья, и только для видео с негативными сигналами (`withdraw` / `review`), плюс
   листы из eval. Правка границ на странице ревью исправит края лишь у этой доли, а не у всех
   опубликованных AI-строк. Чтобы она дала те ≈ 16 % рекламы, нужен проход асессоров по *всем*
   опубликованным видео, то есть замедление умножается на объём, которого сегодня нет (бюджет
   детекта 200 видео/день).
6. **Код: идентичность сегмента = `(start, end)`, в ~15 местах.** Правка «на месте» ломает
   голоса, undo и клики (точное совпадение границ: `prv/routes/votes.js:46`,
   `ai/judge/signals.go:151-167`), восстановление строки (`allKept`, `prv/repository/ai.js:13`),
   baseline судьи (`entryKeeps`, `signals.go:258`), защиту от дублей пунктов
   (`ai/judge/review.go:24`), сам `applyVerdict` (`ai.js:69`: пункт со старыми границами больше не
   находит запись), экспорт gold в eval (`scripts/export-review-verdicts.sql:32`), ссылку плеера и
   `cues` пункта (снимки на момент создания). Записи AI-строки целочисленные (Go `int`,
   `jsonb_to_recordset(… int)`), дробная граница ломает судью на парсинге.

## Ошибка границ детектора (held-out, человеческий gold)

| Прогон | пар | \|start\| p50 / p75 / p90 | \|end\| p50 / p75 / p90 | старт поздно > 2 с | конец рано > 2 с | режет контент > 2 с (любой край) | IoU p50 |
|---|---|---|---|---|---|---|---|
| v2.2 batch | 159 | 3.6 / 17.9 / 48.4 | 5.3 / 14.8 / 24.3 | 55 % | 66 % | 8 % | 0.82 |
| — sponsor | 137 | 7.1 / 22.3 / 52.3 | 7.3 / 16.5 / 26.0 | 59 % | 75 % | 7 % | 0.80 |
| — self_promotion | 22 | 0.8 / 2.8 / 5.3 | 1.5 / 2.1 / 3.2 | 32 % | 9 % | 23 % | 0.87 |
| v2.1 batch | 144 | 7.1 / 33.6 / 59.9 | 5.2 / 12.5 / 23.6 | 60 % | 62 % | 9 % | 0.72 |
| v2.2, timing-clean (164 видео) | 122 | 3.3 / 15.6 / 37.8 | 5.5 / 15.1 / 24.3 | 55 % | 66 % | 7 % | 0.84 |

- Правило подводки в v2.2 вдвое уменьшило ошибку старта против v2.1 (p50 7.1 → 3.6). Остаток
  p75–p90 (15–50 с) это выбор не той реплики (питч вместо подводки), не гранулярность реплик.
- Срез timing-clean ничего не меняет: ошибка краёв не от сбитых таймлайнов субтитров. Сбитый
  таймлайн (≈ 22 % видео, сдвиги 4–87 с, ступенями) даёт `unclear` и ложные сегменты, и его
  закрывает фаза 3 (`docs/backlog/ai-timeline-phase-3.md`), а не правка границ руками.
- Осторожно с «reviewed gold»: вердикт `gold_missing` добавляет интервал с границами *пункта*,
  то есть детектора, поэтому на нём ошибка границ 0 по построению (`score-…-reviewed.json`
  показывает start p50 0.2 с, это артефакт). Для границ годится только сырой gold.

Откуда «неправильно вырезано» (any_ad, v2.2 batch, 180 ч): по сырому gold 3 687 с, из них 96 %
ложные сегменты без пересечения с рекламой и 3 % перебег краёв; по reviewed gold 374 с (2.08 с/ч),
48 % ложные (9 сегментов) и 45 % края (107 сегментов, ~1.6 с каждый).

## Варианты

| | Что делает | Скорость асессора | Сложность | Что даёт |
|---|---|---|---|---|
| **0. Ничего** | как сейчас: `sponsor` оставляет сегмент с краями детектора | 1× | 0 | края чинятся только промптом (v2.1 → v2.2 уже дал 2×) |
| **A. Границы в вердикте, без применения** | на пункте показать транскрипт ± 60 с с временем (есть в `prv_ai_runs.transcript`), асессор кликом отмечает первую / последнюю реплику рекламы; поле `bounds_start/end` в `prv_review_verdicts`; AI-строка не меняется; экспорт в eval | ≈ 1.3× (чтение текста, два клика; необязательно) | небольшая: страница, одна колонка, экспорт | набор данных, которого нет: насколько часто и далеко асессоры сдвигают края и сходятся ли два асессора; материал для промпта «границы» и для решения о B |
| **B. Применять правку к AI-строке** | A + `applyVerdict` заменяет запись: старая удаляется, новая с `source: "review"` и границами асессора | как A | большая: все места из п. 6, пункт ↔ запись по id, голоса на старых границах теряются (как в `votes-lost-when-segment-boundaries-shift.md`), тесты e2e / Go, обзор для фронта | края чинятся у видео, прошедших ревью (сегодня: только проблемные) |
| **C. Второй проход LLM «только края»** | для подтверждённого сегмента отдельный вызов по транскрипту ± 90 с, который возвращает границы | 1× | средняя: eval сначала, потом detect | чинит края у *всех* видео, не только у ревью; измеримо офлайн только после A (нет gold по границам) |
| **D. Подтягивать к ручной разметке** | при пересечении с живой разметкой того же типа (IoU ≥ 0.5, автор с рейтингом ≥ 0) брать её края | 1× | средняя | почти ничего: на видео с ≥ 10k просмотров ручных разметок 0–1, их концы расходятся (p90 100 с), и это ровно то, от чего AI-first уходит |

Общая предпосылка для A, B и C: письменное правило границ в карточке «Как решать» и в промпте
(подводка входит, возврат к теме не входит, и т.п.). Без него данные A будут повторять разброс
gold, а B переносить его в выдачу.

## Рекомендация

Не строить правку границ сейчас (B). Сначала A: дешёвый сбор данных на том же экране, без
обязательной работы для асессора, без изменения выдачи. Через 2–4 недели по данным A решать:
если асессоры правят края часто и сходятся между собой, идти в C (чинит все видео, цена
асессора не растёт) и оставить B как инструмент точечной правки на проблемных видео; если правят
редко или расходятся, закрыть вопрос правилом границ в промпте.

Причины в порядке веса: ошибка краёв не нарушает правило владельца (контент почти не режется),
а recall дешевле добирать промптом, чем руками; правка на ревью достаёт только видео с
негативными сигналами; человеческая точность границ без правила не лучше детектора; B трогает
ключ идентичности сегмента во всей системе.

## Открытые вопросы

- Определение границ: входит ли подводка, входит ли «ссылка в описании» после возврата к теме.
  Решение владельца, нужно до A.
- Планируется ли проход асессоров по всем опубликованным AI-видео (не только по проблемным)? От
  этого зависит, имеет ли B смысл вообще.
- Точность асессора по тексту против плеера: A может хранить и то, откуда взята граница (клик по
  реплике или введённое время), чтобы сравнить.
